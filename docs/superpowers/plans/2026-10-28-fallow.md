# Fallow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Manifest V3 Chrome extension that lets its owner see every tab across their windows and groups, unload the idle ones in a couple of clicks without disturbing any tab's position, and run that unloading automatically on a chosen idle threshold.

**Architecture:** A service worker owns all state and all decisions. Pure domain modules (`src/domain/`) make eligibility, settings and hostname decisions with no Chrome API access, so the whole policy matrix is unit-testable. A thin adapter (`src/platform/chrome-adapter.ts`) is the only code that touches `chrome.*`, normalising errors into results. UI pages are stateless renderers that ask the worker for a snapshot and send it validated commands; they never decide eligibility. Device-memory sampling runs in the dashboard page under a session-storage leader lock, behind a capability-provider interface so Fallow Probe can register a second provider later without touching tab control.

**Tech Stack:** TypeScript (strict), Vite, React, Vitest for domain and integration tests, `@types/chrome`, Playwright + Chromium for E2E, manual verification on Chrome Stable for macOS. No chart library. No backend. Installed majors as of Task 2: typescript 7.0.2, vite 8.3.5, vitest 5.0.5, react 19.3.1 — all pinned exactly. Vitest's `include` glob covers `tests/**` with `.test.ts`, so Playwright specs must use `.spec.ts`.

**Spec:** `docs/superpowers/specs/2026-10-28-fallow-design.md`, which layers decisions on top of `Fallow_Engineering_Plan.md`. Executors read both. Where they conflict, the design wins.

## Global Constraints

- Manifest V3. Minimum Chrome version `120`. Verify every manifest field and API against that floor; omit or feature-detect anything newer. Development machine runs Chrome 156.
- Permissions are exactly `tabs`, `tabGroups`, `storage`, `alarms`. `system.memory` is `optional_permissions` only. Nothing else — no host permissions, content scripts, `debugger`, `webRequest`, `nativeMessaging`, `processes`.
- `"incognito": "not_allowed"`.
- Never close, move, reorder or navigate a tab. Never navigate a tab to a replacement "suspended" page, including as a fallback when discard fails. Never mutate a tab's `autoDiscardable` flag. Never change a Chrome preference.
- Never render an unavailable measurement as `0` or as an estimate. The string is `Not available in standalone mode`. Never derive a per-tab figure by dividing a total.
- Never label `total - available` as "Chrome RAM", and never equate available RAM with macOS Memory Pressure.
- No durable state in service-worker globals. Register all `chrome.*` listeners synchronously at module top level; handlers await a shared init promise. Initialization is idempotent.
- No artificial keepalive: no `setInterval` in the worker, no no-op messaging or alarm traffic to prevent sleep. One alarm only, named `fallow-eligibility-check`, period 1 minute.
- Never carry a numeric `tabId` or `groupId` across browser sessions as durable identity.
- **A discard mints a new `tabId`** (milestone 0, measured on all 30 discards). `windowId`,
  `groupId`, position, `pinned`, `audible` and `autoDiscardable` all survive; the id does
  not. Treat a tab id as valid only until that tab is discarded, and never re-read a tab
  by the id you asked to discard. `chrome.tabs.onReplaced` is a core path, not an edge case.
- History rows store timestamp, trigger, reason, operation id, session tab id and hostname. Never a page title or full URL.
- All data stays on the device. No remote analytics, no external favicon fetches, no remote code. Bundle every dependency.
- Copy rules: the product is `Fallow`. The name must not contain "Chrome", and the words "Suspend"/"Suspender" appear nowhere in name or UI copy. "Extension" refers only to the Chrome extension, never to the Probe add-on.
- Distribution is load-unpacked for the owner. No store listing copy, screenshots, privacy-policy document or trademark clearance work.

## Review Focus

These five conditions are implied by the spec, uncovered by the happy path, and most likely to bite the owner. Each has a test pinned to the task that owns the code.

1. **A tab URL that does not parse** — `about:blank`, `""`, `chrome://newtab`, a malformed string. Hostname extraction must not throw; the tab is `UNSUPPORTED_URL` and the rest of the inventory still renders. (Task 5, Task 10)
2. **System clock moves backward** — NTP correction or a sleep cycle makes `now - backgroundSince` negative, so a tab reads as used in the future and is never eligible. Negative elapsed clamps to `0` and the timer resets to `now`. (Task 6, Task 9)
3. **Corrupt or stale session/local storage** — an extension update leaves an old or unparseable shape. Reading it must not throw during worker init, or the extension is dead until reinstalled. Unreadable records are discarded and rediscovered; unparseable settings fall back to defaults. (Task 4, Task 8)
4. **Hostile text in a tab or group title** — `<img src=x onerror=...>` as a page title. Rendered as text everywhere, including group chips and the activity log. No `innerHTML`, no `dangerouslySetInnerHTML` anywhere in the tree. Task 16's scan covers all of `src/ui/`, so it re-runs over the dashboard and popup as Tasks 17–19 add them, and again in Task 21's full-suite run. (Task 16)
5. **The dashboard holding the memory-sampling lock is closed** — sampling must not stop forever. A lock whose heartbeat is older than its timeout is reclaimed by another open dashboard. (Task 15)

## Delegation

Each task carries a **Model:** line. `haiku` marks tasks whose signatures and assertions are fully pinned here and which touch no Chrome API races — safe for a lighter model. `sonnet` marks tasks needing judgement about API behaviour or layout. `opus` marks the spike, the executor's race handling, worker lifecycle wiring, and final acceptance, where a wrong call is expensive. A fresh Opus reviewer vets the whole implementation against this plan and the spec after Task 21.

### Task 6: Eligibility policy engine

**Model:** haiku. The matrix below is exhaustive; no judgement is left open.

**Files:**
- Create: `fallow/src/domain/eligibility.ts`
- Create: `fallow/tests/unit/eligibility.test.ts`

**Interfaces:**
- Consumes: Task 3 types and constants, Task 4 `DEFAULT_SETTINGS`, Task 5 `isSupportedUrl`/`hostnameOf`/`matchesProtectedSite`.
- Produces:

```ts
export type EligibilityMode = 'auto' | 'manual-bulk' | 'manual-single';
export type EligibilityInput = {
  tab: TabFacts; settings: Settings; activity: TabActivity | null;
  mode: EligibilityMode; now: number;
  graceUntil: number | null; dashboardOriginTabIds: readonly number[];
};
export function decide(input: EligibilityInput): Decision;
export function backgroundElapsedMs(activity: TabActivity | null, now: number): number;
export function lifecycleOf(tab: TabFacts): LifecycleState;
```

`decide` is pure and total: it collects **all** applicable reasons rather than returning the first, because `Fallow_Engineering_Plan.md` §10 states multiple protections may coexist and the dashboard shows each one. `eligible` is `reasons.length === 0`.

Mode rules, from design §8 and §11.5:

| Check | `auto` | `manual-bulk` | `manual-single` |
| --- | --- | --- | --- |
| Configured threshold (`NOT_OLD_ENOUGH`) | applies | ignored | ignored |
| 60s floor (`USED_RECENTLY`) | applies | applies | ignored |
| Startup grace (`STARTUP_GRACE`) | applies | ignored | ignored |
| `DASHBOARD_ORIGIN` | ignored | applies | ignored |
| All other protections | apply | apply | apply |

`STARTUP_GRACE` and `DASHBOARD_ORIGIN` are ignored under `auto` and `manual-bulk` respectively for reasons the spec gives: grace exists only to stop an automatic cascade, and the threshold under `auto` is always at least the floor, so `DASHBOARD_ORIGIN` could never change an automatic decision.

`backgroundElapsedMs` owns Review Focus 2: it clamps a negative difference to `0`.

```ts
export type Scope =
  | { kind: 'tab'; tabId: number } | { kind: 'tabs'; tabIds: number[] }
  | { kind: 'window'; windowId: number } | { kind: 'group'; groupId: number }
  | { kind: 'all' };

export type Preview = {
  operationId: string; mode: EligibilityMode; scope: Scope;
  eligibleTabIds: number[];
  skipped: Array<{ tabId: number; reasons: ReasonCode[] }>;
  skippedCountsByReason: Partial<Record<ReasonCode, number>>;
};
export type BatchReport = {
  operationId: string; trigger: Trigger;
  requested: number; confirmed: number; alreadyUnloaded: number;
  skipped: number; failed: number; unknown: number;
  results: UnloadResult[]; cancelled: boolean;
};

export interface Executor {
  preview(scope: Scope, mode: EligibilityMode, now: number): Promise<Preview>;
  execute(scope: Scope, mode: EligibilityMode, trigger: Trigger, now: number): Promise<BatchReport>;
  cancel(operationId: string): void;
  reconcileUnfinished(now: number): Promise<BatchReport[]>;
}
export function createExecutor(deps: {
  adapter: ChromeAdapter; inventory: Inventory; tracker: Tracker;
  settings: SettingsRepo; history: HistoryRepo; session: SessionRepo; storage: StorageArea;
  now: () => number; sleep: (ms: number) => Promise<void>;
}): Executor;
```

`now` and `sleep` are injected so the confirmation window is testable with fake timers.

Hard rules, each with a test below:
- **Revalidate immediately before each discard.** Re-read settings and that single tab; re-run `decide`. Preview eligibility is never permission to act later.
- **Confirm by observation.** `confirmed` increments only after a re-read shows `discarded: true`. Retry the read with bounded backoff for at most `DISCARD_CONFIRM_TIMEOUT_MS`, then record `unknown`. Never re-issue the discard.
- **No fallback.** On any failure the tab is left exactly as it is. No close, no navigate.
- **Bounded work.** `auto` takes at most `AUTO_BATCH_MAX` candidates, oldest `backgroundSince` first. Manual batches process in chunks of `MANUAL_CHUNK_SIZE` and revalidate between chunks. Requests are sequential.
- **Automation off stops the batch.** Before each chunk under `trigger: 'automatic'`, re-read settings; if automation is now off, stop and mark the report `cancelled`.
- **Crash-safe records.** Write an in-flight record to `storage.session` under `KEYS.batch` before the first request and clear it on completion. `reconcileUnfinished` turns a surviving record into `unknown` results — it never replays a manual command.

- [ ] **Step 3: Implement `executor.ts`**

Confirmation loop: after `adapter.discard`, if the returned `facts.discarded` is `true`,

the id the owner's action referenced and the id the preview showed. Carry the new id in an
added `newTabId?: number` field so the tracker can migrate its activity record.

`cancel` sets a flag checked between tabs and between chunks; an already-issued request is
allowed to finish.
